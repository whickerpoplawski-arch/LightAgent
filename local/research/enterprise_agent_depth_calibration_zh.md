## 1. 尺子声明

| 尺子 | 问什么 | 本文件是否采用 |
| --- | --- | --- |
| **公司产品可上线** | 全员能办完一类真实办事链路；制度/数字可审计；权限与数据不出域；缺陷可回归、可继续训 | **是（主尺子）** |
| 实习 JD 级生产力 Agent | FACTS/RAGAS/GAIA、递归 Swarm、THE AGENT COMPANY / WorkArena 终局台架 | **部分对齐**——协议与缺口对照；**不**以全榜刷分为产品必达 |
| 生活助手日用达标 | 忌口/例程/群聊少回声/长久省额度 | **否**——仅作「相对升降级」对照 |

**用户**：公司内每个员工（销售 / 研发 / 运营 / 行政等），多角色、多权限域，非单一「主人」生活场景。  
**目标**：提高工作效率——写邮件、查制度、办流程、跨系统工具、多角色协作。  
**模型**：公司内自部署 + 后训练（SFT / 继续训）→ 可控、可评、可继续训；**Agent 侧缺陷不能全甩给「换更大公网模型」**。  
**合规**：权限、审计、数据不出域、工具 ACL；制度条款与数字幻觉成本高。  
**产品边界**：可上线的公司产品，不是论文榜刷分机器。

**关系**：JD 总评「不够格」（A/C 接近，B/D/E 未达）在这把尺子下**多数仍成立，且 A/C 也要从「接近」抬到「产品可验收」**。生活助手里刻意砍掉或降级的职场台架 / 受限 handoff / 制度 RAG，在本尺子下要**回升**。

## 2. 与生活助手校准的差异表

| 维 | 生活助手深度档 | 公司产品深度档 | 升降级 | 理由（一句） |
| --- | --- | --- | --- | --- |
| **A 质量** | 做到够用即可 | **必做到位**（制度/数字/ACL/审计） | **升级** | 幻觉成本从「推错菜」变为「错制度/错金额/越权调用」 |
| **B 飞轮** | 必做到位（个人忌口 Dream） | **必做到位**（企业知识巩固 + 租户/部门隔离） | **同档换靶** | 巩固对象从偏好/忌口 → 制度摘要、工单模式、角色 SOP；必须带 ACL |
| **C 规划记忆** | 做到够用即可 | **必做到位**（规划 + Tool + RAG 主路径） | **升级** | 办事链路需要浅～中深规划与制度/工单/邮件 RAG |
| **D 多智能体** | 够用 Room / 刻意不做 Swarm | **够用偏深**：受限 handoff / 角色 Team；无界递归 Swarm **后置** | **明显升级** | 跨角色办一件事是产品面；仍禁无边界 Swarm |
| **E 长程评测** | 抗遗忘+硬事实必达；生产力台架不做 | **必做到位**（跨会话 + ACL 共享 KB）；办事台架 **子集必建**；全榜 **后置** | **升级（台架回升）** | 无「办完一件事」终态则无法宣称提效 |

深度档四选一（与生活助手同名，含义按公司产品改写）：

| 档 | 含义 |
| --- | --- |
| **必做到位** | 不做则「全员可上线提效」立不住；P0/P1 产品债 |
| **做到够用即可** | 有体感与合规收益，到验收线就停，防过度工程 |
| **刻意不做或后置** | ROI 低、合规风险高、或易引入无界递归；明确砍掉或 P2+ |
| **只建评测不建产品** | 用金标/子集探针盯回归与继续训；不把外部全榜当发布门禁 |

## 3. 各维深度校准

### A. 质量缺陷（事实 / 遗漏 / 工具 / 遵指 / 完成）

| 项 | 内容 |
| --- | --- |
| **公司产品目标态** | 制度问答可溯源；报销/报价数字不错；该调的工具在 ACL 内、不该调的绝对不调；多约束（角色+密级+流程）不漏；任务有可审计终态（草稿/工单号/checkpoint）。 |
| **建议深度** | **必做到位**（比生活助手更深） |
| **具体要做什么（可验收）** | 1. **制度/政策金标集**（内网 FAQ 或脱敏制度切片）+ grounded 裁判：回答须引用或绑定条款 id，禁止「听起来对」 2. **IFEval/FollowBench 企业改写子集**（否定遵指：「不要发邮件」「只查不改」「用正式口吻」）常绿 3. **工具 ACL**：按角色/部门 allowlist；越权调用硬拒 + 审计日志 4. 工具 must/forbid AST（BFCL 精神）对**内网工具面**（邮件草稿、工单、制度检索、日历）保绿 5. 数字/金额类：可解析字段校验或二次确认策略（产品策略，非仅 prompt） 6. （评测）FACTS 风格 multi-judge **子集**或自建「制度 grounded」裁判；**不必**上线 FACTS 全榜产线 |
| **不要做成什么** | 把公网 FACTS/RAGAS/GAIA 全榜当发布门禁；用更大公网模型「掩盖」Agent 无引用、无 ACL；生活向忌口启发式当企业事实主路径。 |
| **相对生活助手** | **升级**：生活助手「卡+启发式够用」→ 公司产品「金标 grounded + ACL + 审计」。 |
| **相对 JD** | **对齐子集**：JD A「接近」要抬到可验收；仍用子集裁判，不刷全榜。 |

### B. Context 飞轮 / 自进化

| 项 | 内容 |
| --- | --- |
| **公司产品目标态** | 用几周后少重复问「我们休假怎么算」；过期制度被 supersede；部门知识不串到无权限员工；后台巩固可审计、可回滚。 |
| **建议深度** | **必做到位**（企业知识巩固 + 权限域；**不是**个人忌口 Dream 照搬） |
| **具体要做什么（可验收）** | 1. `run_due` 真正执行：**merge** 近重复制度摘要/工单模式 + **supersede** 过期条款；可观测 diff 2. **租户 / 部门 / 角色作用域**（对齐 Mem0 `user_id`/`app_id` 精神，升级为 `tenant_id`/`dept_id`/`acl`）；consolidate **禁止跨域合并** 3. 门闩：minHours / minSessions / minMemories + 文件/行锁，防风暴巩固烧内网 GPU 4. pin / 制度卡 / 合规红线 **跳过**自动 consolidate 或需人工审批 5. 可选低频 **synthesis**：部门级 pattern（「差旅报销常见驳回点」），默认低频、可关 6. 审计：巩固前后版本、操作者（系统/人）、可回滚 |
| **不要做成什么** | Voyager 技能库式「偷偷学出可执行攻击脚本」；跨租户共享 consolidation；每轮 LLM consolidate；把个人生活忌口 Dream UX 原样搬进企业（无审批、无 ACL）。 |
| **相对生活助手** | **同档换靶**：仍必做 consolidate，但对象与隔离模型换成企业知识。 |
| **相对 JD** | **对齐**：关掉 `run_due=[]` 否定探针；进化可观测 = 错误率↓ / 重复问↓，非技能库叙事。 |

### C. 规划 · Tool-use · 记忆/RAG · Reasoning

| 项 | 内容 |
| --- | --- |
| **公司产品目标态** | 「帮我走完差旅报销」能拆成可检查步骤；制度 RAG 命中条款；邮件/工单工具在 ACL 内；闲聊不把进行中流程推歪；失败可恢复。 |
| **建议深度** | **必做到位**（规划 + Tool-use + RAG 进**主路径**；Flow/DAG **按流程类任务打开**） |
| **具体要做什么（可验收）** | 1. 流程类任务：LightFlow / LightDAG 或等价步骤图 **可开关接入**主路径（默认对「报销/入职/采购」模板开） 2. **制度 / 工单 / 邮件** RAG：检索 → 引用 → 作答；context-recall 类探针（RAGAS 精神子集） 3. LifeGoal/工作目标：拒滥拆 + 单 in_progress + cancel/resume；跨会话续办 4. 工具面：内网连接器（邮件草稿、工单、KB、日历）稳定；危险写操作需确认/双人策略（产品策略） 5. BudgetLimits / cancellation / checkpoint 接到主对话（对齐 harness 生产评估缺口） 6. （评测）自建「办一件事」多步终态（AppWorld/τ 精神：终局状态相等） |
| **不要做成什么** | 默认无界 ToT 烧 GPU；把 coding agent「计划模式」整套无 ACL 搬来；向量库无密级过滤；浏览器任意站外爬取当默认（数据出域）。 |
| **相对生活助手** | **升级**：生活助手「日用关 Flow/DAG、够用即可」→ 公司产品「流程模板开规划 + RAG 主路径」。 |
| **相对 JD** | **对齐接近→达标路径**：深规划/RAG 不再后置。 |

### D. Multi-Agent（协作 / Team / 受限 handoff）

| 项 | 内容 |
| --- | --- |
| **公司产品目标态** | 「法务+财务+业务」在同一办事链路各司其职；主助理保留终稿权或显式 handoff；少回声、可审计谁说了什么；跨角色不互啄无权数据。 |
| **建议深度** | **做到够用偏深**（受限 handoff / 角色 Team **值得做**）；无边界递归 Swarm **刻意不做或后置** |
| **具体要做什么（可验收）** | 1. 在 Hosted Room / 协作层之上：增加 **agents-as-tools** 或 **受限 handoff**（所有权转移可记录、可回主助理） 2. 角色 Team 模板：如「差旅」「合同评审」「客服升级」——任务队列或短图，**非**自由互啄 3. 选麦：规则 / 流程状态机优先；LLM Host **可选、默认关或仅模板内** 4. 共享层：制度卡/工单状态 **只读 + ACL**；digest 继续剥离 ephemeral；禁止 transcript 全文互啄 5. `@` / max_speakers / 敏感外发门闩保留并扩展到企业敏感词（发客户、改权限） 6. （评测）多角色办事剧本：发言顺序、终稿权、越权静默 |
| **不要做成什么** | ReDel 式运行时无限生原子 Agent；AG2 `auto` 选麦默认开；CrewAI 流水线冒充「员工群聊 UI」却无审计；`LightSwarm.run` 无守卫默认进房。 |
| **相对生活助手** | **明显升级**：生活助手「Room 够用 > Swarm」→ 公司产品「Room + 受限 handoff/Team」；仍 **不做**无界递归 Swarm。 |
| **相对 JD** | **部分对齐**：JD「未达」要动态编排——用**受限、可审计**编排对齐，不追论文递归。 |

## 5. 自部署后训练模型对 Agent 层的含义

内网自部署 + SFT/继续训改变的是**责任边界**：模型可变、可评、可再训，但 **Agent 编排、工具 ACL、记忆巩固、评测门禁** 仍是产品必达层，不能「换更大模型」抵消。

| 层 | 含义 | 可验收动作 |
| --- | --- | --- |
| **提示词 / 系统卡** | 后训练已注入公司口吻与部分 SOP 时，Agent 侧应减「重复说教」，增「结构化槽位 + 工具契约」；版本与模型 checkpoint **绑定** | 模型版本号写入审计；换 checkpoint 必跑回归集 |
| **工具 schema** | 后训练对正确 schema 敏感：字段名/枚举稳定；错误 schema 会固化坏习惯 | schema 变更 = 评测门禁 + 可选再 SFT 数据 |
| **制度卡 ≈ 生活「忌口卡」** | 硬约束从「不吃海鲜」变为「密级 / 审批阈值 / 禁止外发客户数据」；注入只见 **active + 有权限** 条款 | 制度卡 supersede + ACL 过滤注入 |
| **评测回归** | 每次继续训 / 提示词改 / 工具改：跑 A 子集（制度 grounded + IFEval 改写）+ 办事终态子集 + ACL 越权负例 | CI：fail = 禁止晋升该 checkpoint |
| **飞轮与再训分工** | consolidate 产出的 pattern **可导出为再训语料候选**（人工审），但自动 consolidate ≠ 自动写入基座；防污染 | 人审队列；租户隔离导出 |
| **幻觉治理** | 数字与制度：**检索 grounded 优先于参数记忆**；后训练负责风格与工具格式，事实以 KB/制度卡为准 | 无检索命中则拒答或标「未找到条款」 |
| **成本与容量** | 内网 GPU 有预算：门闩巩固、默认关无界 ToT、Room max_speakers，与生活助手「省额度」同构但计量对象换为 GPU 小时 | 预算仪表 + 每任务 LLM 次数上限 |

**原则**：模型侧解决「会说公司话、会填工具参数」；Agent 侧解决「该不该说、该不该调、谁有权看、办没办完」。两边都缺则产品不可上线。

## 6. 优先级排序（公司产品 ROI）

### P0（不上线就先做）

1. **A：制度/数字质量底线** — 制度金标 grounded 子集 + 工具 ACL + 审计日志 + 否定遵指/越权负例；换模型 checkpoint 必回归。  
2. **C：办事主路径** — 制度/工单/邮件 RAG + 流程类任务开浅～中规划（Flow/DAG 或等价）+ Budget/取消/checkpoint 接线。  
3. **E：ACL 共享 KB + 跨会话续办** — 租户/部门作用域事实层；进行中流程跨会话可恢复；自建「办一件事」终态探针（或 TAC/WorkArena 子集协议落地）。

### P1（体感与协作明显）

1. **B：企业 consolidate** — `run_due` merge/supersede + 跨域禁止合并 + 门闩 + 可回滚审计；可选低频部门 synthesis。  
2. **D：受限 handoff / 角色 Team** — 差旅/合同等 1–2 个模板；主助理终稿权默认；LLM 自由选麦默认关。  
3. **A/C 评测加深** — IFEval 企业改写 + RAGAS 精神 context-recall 子集进 CI。

### P2（后置或只评测）

1. 无边界递归 Swarm / ReDel 运行时生 Agent。  
2. THE AGENT COMPANY / WorkArena / AssistantBench / GAIA **全榜**刷分。  
3. 组织级全员可读 Graph 无 ACL；Voyager 式技能库自动执行。  
4. 公网 FACTS multi-judge 全流水线（有内网金标则可替代）。

## 7. 校准原则（写入约束）

1. **该深**：制度 grounded、工具 ACL、审计、流程规划+RAG、跨会话续办、ACL 共享 KB、受限多角色协作。  
2. **不当产品必达**：外部全榜刷分、无界递归 Swarm、无 ACL 全图共享。  
3. **B**：企业知识巩固 + 租户隔离；不是个人忌口 Dream 换皮。  
4. **D**：受限 handoff / 角色 Team 优先于通用递归 Multi-Agent。  
5. **E**：办事子集台架 + LoCoMo/LongMemEval 企业改写；全榜后置。  
6. **A**：金标 + ACL 优先于「换更大公网模型」。  
7. **模型**：自部署后训练与 Agent 层分工清晰；缺陷可回归、可再训，不可甩锅。

## 8. 一句话总判

按**公司产品级 Agent**定位：应深挖 **A 制度/ACL/审计质量**、**C 规划+工具+RAG 办事主路径**、**E 跨会话 + ACL 共享 KB + 办事子集台架**，并以 **B 企业巩固飞轮**、**D 受限 handoff/Team** 为紧随其后的产品能力；生活助手里砍掉的职场台架与动态编排要**有边界地回升**，论文全榜与无界 Swarm **仍可后置**。

## 9. 现状锚点（实事求是）

| 组件 | 现状一句话 | 对公司产品含义 |
| --- | --- | --- |
| ConstraintCard | 主题词表 + supersede；生活忌口向 | 需演化为**制度卡 + ACL**，不能直接当政策引擎 |
| LifeGoal | workspace JSON；单 in_progress | 可作办事目标雏形；缺流程 checkpoint 与跨系统终态 |
| Memory jobs | `enqueue` 有；`run_due` **故意 return []** | 企业飞轮未起步；P1 必补且加租户隔离 |
| Hosted Room | `@` → 关键词模板 → host_only；单层 | 协作品面有壳；缺受限 handoff / 企业 Team 模板 |
| 工具面 | web_search/fetch 等；无企业 ACL 矩阵 | 上线前必须角色 allowlist + 审计 |
| 评测 | L0/L3/jd_bar_v2 切片绿；外部大榜未跑 | 切片≠可上线；需制度金标 + 办事终态子集 |
| 模型假设（新） | 当前跑次多为公网/代理 API | 切换内网 checkpoint 后，**回归门禁**比换供应商更关键 |

**本校准不要求本轮改上述生产行为**；改深度目标与优先级，供公司产品排期。
